# 1. プロジェクト説明
## プロジェクト概要
案件マッチングAIの構築し、案件アサインフローをAXする<br>
- 案件情報の民主化：全社員が全案件情報にアクセスできる
- アサイン基準の明確化：何をどこまでできれば面談に進めるのかの基準をAIで構築
- 専門性を活かす分業の徹底：エンジニア/マネージャー/営業が役割分担し効率的な業務遂行を可能に

## ビジョン
SES企業特有の営業主導のアサインフローをエンジニア主導にし、組織構造の変革を目指す<br>
営業やマネージャーがエンジニアに案件を提案する形式は、エンジニアの自律性と自己効力感を低下させ、ハイレベル人材ほど「AMBLはキャリア実現性が低い環境だ」とみなしてしまう要因になっていると考える<br>
案件アサインフローをAXによって無駄のない仕組みに変え、<br>
　・ハイレベル人材の定着率向上<br>
　・人材レベルの底上げ<br>
　・営業・マネージャーの非付加価値業務削減<br>
などを実現する

## 本プロジェクトの性質と役割
本プロジェクトは、機械的に案件参画を確約するものではない<br>
「キャリアの不確実性」を排除し、アサインの成功確率を極限まで高めることを目的とする<br>
エンジニアが自律的に目標を定め、客観的根拠を持って案件を選び取れる環境を構築することで、キャリア実現に対する納得度とエンゲージメントを最大化させる狙い

# 2. 現状共有とプロジェクトの効果説明
## 現状のアサインフロー共有
以下の流れで案件が決まる
1. 現在の案件アサインフローは、エンジニアが案件変更希望をマネージャーなどに伝えることから始まる[エンジニア → マネージャー]
2. 変更理由、希望条件、キャリアビジョンを共有し、それをもとにマネージャーが営業や部長と連携して案件を探してエンジニアに提案する[マネージャー → 営業・部長]
3. エンジニアは探された案件に対して参加可否を伝え、参加意思があれば面談等に進む[マネージャ → エンジニア]
4. 提示案件を拒否することも可能だが、まれに待機期間が長引く等の状況が重なると、営業が先方と参画の話をつけてきて、エンジニアは参画決定を事後報告されることもある[営業 → エンジニア]


## 現場の課題
- エンジニア目線
    - 案件の全容や参画基準がブラックボックス化しており、キャリア実現性が低い
    - 多方面へのビジョン共有も相手の技術理解度に依存し、正確に伝わらない
- マネージャー目線
    - 個別最適のヒアリングと条件調整に膨大な工数が奪われている
    - 会社都合による決定も論理的な裏付けが乏しいため説明コストが高く、保守的なアサインに終始しがち
        - 自身の営業経験から、顧客とのつながり優先や既存案件死守のための人材確保が必須、など「エンジニアにとって不都合な事実」がある中、エンジニアの希望と板挟みになっているのでは、と仮説を持っている
- 営業目線
    - 現場業務の専門性が高く、表面的なマッチングになりがち
    - 本業の案件獲得と細かなアサイン調整の板挟みにより、エンジニアの信頼を損なうミスマッチが発生
        - 自身の営業経験から、「AMBLの売上向上」が絶対視される評価体系になっていて、エンジニアのキャリアよりも数値目標を追うことに注力しているのでは、と仮説を持っている

## AX実現後の案件アサインフロー
AX実現後のアサインフローは下記のようになる
1. エンジニアが自分で案件を検索し、希望案件に必要なスキル・経験を積むための計画を立て、実行する[エンジニア]
2. 参画可能な根拠が提示できるようになったら、参画希望案件を選択・参画可能根拠をAIとともに作成し、それらをマネージャーに共有する[エンジニア → マネージャー]
3. マネージャーは案件要件と参画可能根拠を比較し、面談に進めるかどうかの意思決定をする[マネージャー]
4. 参画不可と判断した場合、その理由とネクストアクションを提示しエンジニアに差し戻す[エンジニア → マネージャー]
5. 参画可能と判断した場合は、営業に面談日程調整の依頼を投げる[マネージャー → 営業]
6. 面談を設定し、その日時を連携する[営業 → マネージャー → エンジニア]

## AX実現後の現場の課題の変化
- エンジニア目線
    - 案件アサインまでの道筋が明確になり、キャリア実現性の向上を実感できる
    - 希望案件・参画可能根拠・キャリアビジョン等がフォーマット化されるため、説明コストが下がる
- マネージャー目線
    - 参画判断に必要な情報がフォーマット化されるため、パーソナライズ工数が削減される
    - 判断軸がAIによって可視化されているため「条件は満たしているけど会社都合で今回は難しい」という説明でもエンジニアは納得しやすく、無駄な説明コストがかからない
- 営業目線
    - 分業が実現されるため、案件情報共有工数が無くなることも相まって、案件獲得や単価向上など営業にしかできない業務に注力できる
        - 「案件アサイン人数」がKPIにあるならKPIの再設計が必要

## 本プロジェクトの予想される効果
- 主体的なキャリア構築による在籍期間で最大化:
    - エンジニアが主体的にキャリアを選べる環境を整えることで、離職率を下げ、1人あたりの在籍期間と総売上を最大化する
- 全社横断での共通言語を用いた会話による工数削減:
    - 案件情報を民主化することで、エンジニア/マネージャー/営業が同じ情報にアクセスできるようになる
    - 従来会社都合の営業判断は濁されてエンジニアに伝えられていたが、濁す工数が無駄であり、濁されたエンジニアの不信感を買っていた
    - 案件情報がまとまること/案件の参画可否の理由が明確になることで、非生産的な情報収集や情報加工・ドキュメンテーション・マッチング業務を削減でき、案件獲得や人材育成といった売上に直結する施策が打ちやすい土台が整う
- 採用競争力の強化:
    - 「AIを使用しエンジニア主導で案件を選択できる」という環境は、他社にはない強力な差別化になる

# 3. プロジェクト開発計画
## 案件アサインフローAXに向けて開発するプロジェクト一覧
下記のようなRAG・AIエージェントをコントロールするオーケストレーションAIの構築を検討
- 案件情報の民主化：全エンジニアが全案件情報にアクセスできる
    - スプレッドシート・メール・Slackなど散逸的に管理されており、エンジニアに共有が難しかった案件情報を統合できるようGraphRAGを使用した案件検索システム
- アサイン基準の明確化：何をどこまでできれば面談に進めるのかの基準をAIで構築
    - 営業・マネージャーの属人的な判断で参画可否が判断されていたものを、案件要件から必要な経験・スキルセット・マインドセットなどAIで言語化し、それらの達成度合いで判断できるようにマッチングスコアを出力するAIエージェント
    - 上記で出力したスコアをもとに、不足しているスキル・経験を言語化し、いつまでに何をすれば参画可能性を上げられるのかというキャッチアップ計画を出力できるAIエージェント
    - 参画希望の案件に入れなかった場合の代案として類似案件をレコメンドするAIエージェント
    - ジュニア層向けにキャリアパスを提示するAIエージェントとそれらに合わせた案件を提示するAIエージェント
- 専門性を活かす分業の徹底：エンジニア/マネージャー/営業が役割分担し効率的な業務遂行を可能に
    - エンジニアが本プロジェクトを使用した際、スキルや経験を蓄積し、営業の補助資料として使えるようフォーマット化したエンジニア情報を出力するAIエージェント
    - 参画において不都合な事実の伝え方を悩む工数を削減するために、会話の共通言語として「案件ベース」で話せる仕組みづくり
- 別件：システム構築によって今後派生が考えられる領域
    - 選考プロセス効率化のため書類選考時に具体的案件想起をシステム化するためのAIエージェント
    - 採用競争力強化含め本システムの効果を定量化するための仕組みづくり
    - エンジニアの実績・評価を蓄積し、理想のロールモデルを作成・共有できる基盤づくり

## 直近の開発
案件アサインフローのAXを達成するために、プロジェクトの核となる『案件検索エンジン』を作成する

### ■ 開発の必要性：なぜ「検索エンジン」からなのか
エンジニアが自律的にキャリアを形成するためには、「そもそもどんな選択肢 = 案件があるのか」を自分自身で把握できることが絶対条件<br>
現状、案件情報にアクセスできないことがキャリアの不透明さを生み、離職の原因になっていると考える

### ■ 現状と課題
- 情報のブラックボックス化:
    - 案件情報はスプレッドシート、Slack、個人メール、そして営業担当の「頭の中」に散らばっており、エンジニアが横断的に参照できる場所がない
- 手動統合の限界:
    - 全情報を1つのスプレッドシートに手動でまとめ直すには膨大な工数がかかり、更新頻度の速い案件情報の鮮度を保つことは現実的ではない

### ■ 解決策：GraphRAGによる「散逸したデータの動的統合」
情報を一箇所に「集める」のではなく、散らばったままの情報をAIが「繋ぎ合わせる」アプローチを採用
- GraphRAGの活用:
    - 異なるソースから情報を自動吸い上げ、AIが技術要素やプロジェクトの繋がりを解析して意味のネットワークを構築
- 自律的探索の実現:
    - エンジニアは、キーワード検索だけでなく「自分のやりたいこと」という抽象的な検索条件から、会社全体に眠る最適な案件を自ら発見できるようになる

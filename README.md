## プロジェクト概要
案件マッチングAIの構築し、案件アサインフローをAXする

## ビジョン
案件アサインフローのAXによる「高収益・高定着」組織への変革<br>
単なるシステム導入ではなく、SES事業の核である「アサイン」の仕組みをデータ駆動型にアップデートし、「エンジニアが辞めず、勝手に育ち、高単価案件が次々と決まる」体制を構築します

## 現状の共有
現在の案件アサインフローは、エンジニアが案件変更希望をマネージャーなどに伝えることから始まる<br>
変更理由、希望条件、キャリアビジョンを共有し、それをもとにマネージャーが営業や部長と連携して案件を探しエンジニアに提案する<br>
エンジニアは探された案件に対して参加可否を伝え、参加意思があれば面談等に進む<br>
提示案件を拒否することも可能だが、まれに待機期間が長引く等の状況が重なると、営業が先方と参画の話をつけてきて、エンジニアは参画決定を事後報告されることもある

## 現状の課題と付随する損失
- 採用・離職コストの増大:
    - キャリア実現可能性や成長実感が持てないハイエンド層の離職が多いと仮説を持つが、それら1人あたり数千万円/年の売上・採用・教育費の損失が発生する
- 営業・マネージャーの「目利き」の限界:
    - 営業/マネージャーのIT知識の差により、高単価を狙えるはずのエンジニアを低単価な保守案件に留めてしまうミスマッチによって一人当たり数百万円/年の売上損失が発生する
- マネジメント工数の肥大化:
    - マネージャーが「案件探し」という非付加価値業務に忙殺され、本来の「評価・育成」に時間を使えず強い組織が育たない

## 本プロジェクトがもたらす3つの戦略的価値
- 売上の最大化:
    - エンジニアが主体的にキャリアを選べる環境を整えることで、離職率を下げ、1人あたりの在籍期間と総売上を最大化する
- 工数削減による生産性向上:
    - 非生産的な情報収集・ドキュメンテーション・マッチング業務を削減することで、案件獲得や人材育成といった売上に直結する施策が打ちやすい土台が整う
- 採用競争力の強化:
    - 「AIがあなたのキャリアパスに最適な案件を客観的根拠を持って提案してくれる」という環境は、他社にはない強力な差別化になる

## 本プロジェクトで達成したいこと
- キャリアビジョンと目標設定の戦略的動機
    - 現状:
        - 目標設定の粒度が個人によって異なり、志向と案件が乖離しがち
    - 理想:
        - AIが目標設定データから潜在的なキャリア志向を構造化
        - 会社が求めるスキルセットと個人のビジョンを高い精度で同期させ、「社員の意欲がそのまま会社の成長エンジンになる」状態を創出する
- データ駆動型のスキルギャップ分析と育成加速
    - 現状:
        - 案件参画に必要なスキルの定義が曖昧で、学習が個人の努力頼み
    - 理想:
        - 志望案件に対するスキルギャップをAIが客観的に可視化
        - 参画に向けた具体的な「キャッチアップ・ロードマップ」を自動策定することで、若手・ボリューム層の戦力化スピードを最大化
- 公平性の高いアサイン意思決定プロセスの確立
    - 現状:
        - 経験則や属人的な判断によるマッチングが、エンジニアの不信感や離職を招いている可能性がある
    - 理想:
        - スキル・実績・志向性をスコアリングし、誰が見ても納得できる「客観的な判断軸」を構築
        - 「実力と希望が正当に反映される文化」をシステムで担保し、ハイレベル人材の定着率（リテンション）を向上
- アサインにおけるガバナンスと組織的透明性の確保
    - 現状:
        - 社内事情によるアサイン変更が、説明不足により「不本意な参画」として捉えられている可能性がある
    - 理想:
        - 参画の背景や組織的な判断理由をデータに基づいて明示できる体制を整備
        - 組織としての説明責任を果たすことで、たとえ希望通りでない場合でも納得感と信頼関係を維持できる強固な組織基盤を構築
- ロールモデルの可視化と評価の妥当性向上
    - 現状:
        - 評価基準が不透明で、何をすれば昇格できるかの具体例が不足している
    - 理想:
        - 上位グレード人材の行動特性や経験案件をAIで抽出し、「理想のキャリアパス」としてモデル化
        - 「何を達成すれば評価されるか」を可視化し、公平な相対評価と、全社員の自律的なスキルアップを促す仕組みを構築

## 直近の開発
上記を達成するための核となる『案件検索エンジン』を作成する

### ■ 開発の必要性：なぜ「検索エンジン」からなのか
エンジニアが自律的にキャリアを形成するためには、「そもそもどんな選択肢（案件）があるのか」を自分自身で把握できることが絶対条件<br>
現状、案件情報にアクセスできないことがキャリアの不透明さを生み、離職の直接的な原因になっていると考える

### ■ 現状と課題
- 情報のブラックボックス化:
    - 案件情報はスプレッドシート、Slack、個人メール、そして営業担当の「頭の中」に散らばっており、エンジニアが横断的に参照できる場所がない
- 手動統合の限界:
    - 全情報を1つのスプレッドシートに手動でまとめ直すには膨大な工数がかかり、更新頻度の速い案件情報の鮮度を保つことは現実的ではない

### ■ 解決策：GraphRAGによる「散逸したデータの動的統合」
情報を一箇所に「集める（手入力する）」のではなく、散らばったままの情報をAIが「繋ぎ合わせる（統合管理する）」アプローチを採用
- GraphRAGの活用:
    - 異なるソース（スプシ、チャット、メール）から情報を自動吸い上げ、AIが技術要素やプロジェクトの繋がりを解析して「意味のネットワーク（線）」を構築
- 自律的探索の実現:
    - エンジニアは、キーワード検索だけでなく「自分のやりたいこと」という抽象的な検索条件から、会社全体に眠る最適な案件を自ら発見できるようになる

## 本プロジェクトの性質と役割
本プロジェクトは、機械的に案件参画を確約するものではありません<br>
「キャリアの不確実性」を排除し、アサインの成功確率を極限まで高めることを目的としています<br>
エンジニアが自律的に目標を定め、客観的根拠を持って案件を選び取れる環境を構築することで、キャリア実現に対する納得度とエンゲージメントを最大化させます

## なぜやるのか
社内の案件参画をAXし、<br>
情報の非対称性によるキャリア実現のしづらさを解消するため

### ■背景
会社として離職率低下を望んでいる<br>
仮説として、案件参画において下記3点がビジョン実現のハードルとなり、ハイレベル人材ほど転職が選択肢に挙がってしまうと考えた
1. どんな案件があるのか分からない
2. 何すれば案件に入れるかが営業やマネージャーの感覚値で不透明
3. 案件に入ったとして望んだ経験ができるか分からない

1番を重点的に解決しながら、2番・3番の緩和を狙えると考えたためこの施策の実施を決めた<br>
また、1番を解決する過程で、「自分が何をしたいかわからない」というジュニア層のキャリアビジョン形成への貢献も検討

## 何をやるのか
案件マッチングAIを構築する

### ■背景
現状案件参画は、営業やマネージャーが案件を探してエンジニアに提案する形式<br>
営業や特定業務への理解が不足しているマネージャーが案件を探すことで望まない案件を紹介される可能性が高まる<br>
また、営業が保有する案件情報はスプシで管理されているもののメールやSlackなどでのやり取りも多く、最新情報がまとめられているわけではないため、点での情報提供になりがち<br>
GraphRAGなどを使用することで散逸的な情報を線として提供/AIによる客観的評価による納得度向上/キャリアビジョンとの主体的すり合わせによって、不本意な案件参画を未然に防ぎ、キャリア実現性を向上できると考える<br><br>
ex) <br>
- 現状（点）：キーワードが完全一致しないと見つからない
    - 「MLOps」と名のつく案件は出るがMLOpsに必要なデータ基盤構築案件はヒットしない<br>
- 理想（線）：技術の相関関係をAIが理解して提案する
    - 「MLOps」と検索するとモデル構築・クラウド環境構築・基盤構築・運用改善・保守、とMLOpsに必要な経験が得られる案件が網羅的にヒットする

### ■北極星
エンジニアが自らキャリアを選択できる情報の透明性を担保すること<br>
※これに寄与しない機能追加や修正は、どれだけ技術的に面白くても「ボツ」にする

## KPI
- 上位5%人材のリテンション
    - (遅行指標) システム構築前後において、単価が高い/単価向上率が高い上位5%の人材に対する離職率の追跡調査
    - (先行指標) システム構築前後における案件参画後の納得度アンケート
- ボリューム層の育成
    - (遅行指標) システム構築前後におけるキャリアビジョンの明確度に関するアンケート
    - (遅行指標) システム構築前後における単価の変化
    - (先行指標) 「システムを1カ月に2回利用する」等のマジックナンバーの達成率
- マネジメント層の工数削減
    - (遅行指標) マッチング成立までのリードタイム比較
    - (先行指標) システム構築前後における案件探しにかかる時間の感覚値に関するアンケート

## How
- データ集約パイプラインの構築（自動吸い上げ）
    - ソースの統合: スプレッドシート（基本情報）、Slack（最新の動向）、メール（詳細条件）から、APIを用いて情報を自動でPull型収集します。
    - LLMによる構造化: バラバラな形式のテキストを、AIが「案件名」「必須スキル」「フェーズ」「現場の雰囲気」といった共通フォーマットに自動変換します。
- GraphRAGによる「ナレッジグラフ」の形成
    - 意味の関連付け: 「MLOps」という言葉を知らなくても、AIが内部で「MLOps ＝ データ基盤 ＋ 監視 ＋ クラウド」という関係性（グラフ）を保持し、最適なマッチングを計算します。
    - キャリアパスの可視化: エンジニアの「現在のスキル」から「目標の案件」まで、どの案件を経験すれば最短で辿り着けるかのルートを導き出します。
- エージェント型ヒアリングUI
    - 対話型インターフェース: エンジニアがAIとチャットするだけで、抽象的な希望を分解し、具体的なキャリアプランとそれに合致する案件を提示します。
- 継続的な改善サイクル
    - フィードバック収集: 実際に参画した後の「納得度」をシステムにフィードバックし、マッチング精度を継続的に向上させる評価基盤を構築します。
